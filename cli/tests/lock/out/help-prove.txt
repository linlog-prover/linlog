$ linlog prove --help
--- status 0
--- stdout
Decide whether a sequent is provable, and print a proof if it is

The fragment of the sequent (MLL, MALL, …) is detected and picks the engine; the first line of the output names both. The exit status is 0 for provable, 1 for unprovable, 3 when the search stopped before deciding, and 2 for an error.

Given several times `--file`, a directory, `--files-from`, or an input format of many sequents (`lines`, `jsonl`, `problems`; on standard input a stream, answered line by line), `prove` decides a batch. Paths are taken literally, with no glob or `~`; a directory is walked in sorted order, links followed, for the files of the input format's extension (`.p` and `.json` for `auto`). Each sequent is named by its path as given, or by its line's name or `FILE:LINE`, and gets one line in input order, `NAME: VERDICT`, as soon as it is decided; with `--format json` a JSON Lines record of `version` and `name` and the outcome's keys, or with the verdict `error` and a `message` (and the library's `error` where it caused it) for an entry that could not be decided. A drawn format writes a file per proved sequent into `--output DIR`. The mode is the flags', or a problem file's column or a record's. The exit status is the worst: an error (2) before unknown (3) before unprovable (1) before proved (0); a batch that holds no sequent is an error, and one interrupted with Ctrl-C, which ends its input, is unknown at best.

Usage: linlog prove [OPTIONS] [SEQUENT]

Arguments:
  [SEQUENT]
          The sequent, such as "A, A -o B |- B"; read from --file when absent, or from standard input by every command but `interact`

Options:
  -f, --file <PATH>
          Read the sequent from this file, or `-` for standard input (but in `interact`, whose commands come from there)
          
          The file's kind is its extension's unless --input-format says otherwise: `.p` an LLTP problem (under --logic, where a command takes it, a TPTP problem of ordinary logic), `.spec` a coverability problem, `.json` a JSON sequent, anything else the text syntax, which may span lines. `prove` takes the flag more than once, and a directory, as a batch.

      --input-format <FORMAT>
          How to read the input, rather than by the file's extension
          
          `lines`, `jsonl` and `problems` hold many sequents, which `prove` decides as a batch.

          Possible values:
          - auto:     By the file's extension: `.p` lltp (tptp under --logic, where a command takes it), `.spec` spec, `.json` json, else text
          - text:     One sequent in the text syntax, which may span lines
          - json:     One sequent in JSON, as `seq json` writes it
          - lltp:     A problem of the LLTP library: its axioms ⊢ its conjecture; the file does not say whether it is intuitionistic, the flags do
          - spec:     A coverability problem in the .spec format of the Mist tool: its rules under !, its initial marking ⊢ its target, a question of affine mode, in which it is decided without --affine
          - lines:    One sequent per line in the text syntax, as `NAME: SEQUENT` or `SEQUENT`; blank lines and everything from `#` on are skipped
          - jsonl:    One JSON value per line: a sequent as `seq json` writes it, or {"name": …, "mode": …, "sequent": …} with the sequent in JSON or as text and the mode named as in `problems`; blank lines are skipped
          - tptp:     A problem of ordinary propositional logic in TPTP syntax, as the ILTP library writes them: its axioms ⊢ its conjecture (with --logic, where a `.p` file is one)
          - problems: The benchmark harness's problem files: `NAME; MODE; EXPECTED; COPIES; SEQUENT` per line, MODE one of classical, mix, affine, affine-mix, intuitionistic, intuitionistic-affine, cyclic, lambek or lambek-star (whose sequents are read as --cyclic reads them); EXPECTED and COPIES are not read
          
          [default: auto]

      --occurrence-limit <N>
          The most subformula occurrences the sequent may have, or `none` (limits.occurrences)
          
          A sequent in JSON can share subformulas, so a small file may stand for a sequent of any size; one beyond the limit is refused before it is unfolded. Occurrences cost some 25 bytes each before any search, and no limit lets through more than about four billion. A text nested deeper than the limit (more `(` or `~` open at once) is refused the same way.
          
          [default: 50000000]

  -i, --intuitionistic
          Intuitionistic linear logic: one formula on the right of ⊢, pars only as implications, and two-sided derivations

  -a, --affine
          Affine logic: a hypothesis may go unused (weakening)

      --mix
          Allow the Mix rule, which proves ⊢ Γ, Δ from ⊢ Γ and ⊢ Δ

      --cyclic
          Cyclic linear logic: the order of the formulas counts, up to rotation, with no exchange (unit-free MLL); the sequent's text is read with the dual of a product reversed, ~(A * B) as ~B par ~A, and the formulas left of ⊢ in the reverse order

      --lambek
          The Lambek calculus: intuitionistic and in the order written, with the divisions A \ B and B / A beside A * B (unit-free), every sequent with a formula left of ⊢; the text is read as --cyclic reads it

      --empty-antecedents
          With --lambek, allow sequents with no formula left of ⊢ (the calculus L*)

      --logic <LOGIC>
          Read the input as ordinary logic, through its translation into linear logic
          
          The input is a formula or a sequent of propositional logic in the syntax below (a `.p` file a TPTP problem, as the ILTP library writes them). `prove` decides its image and reads a proof back as a derivation of LK (classical) or LJ (intuitionistic, minimal), which is checked by the rules of the logic before it is shown; classical logic is decided in affine MALL, with no copy bound, intuitionistic and minimal logic in ILL, under the time limit, so they may be answered unknown, and the JSON output is the search's outcome on the image. `seq print` prints the image.

          Possible values:
          - classical:      Classical propositional logic, derivations in LK
          - intuitionistic: Intuitionistic propositional logic, derivations in LJ
          - minimal:        Minimal logic: intuitionistic without ex falso, false an atom

      --translation <TRANSLATION>
          The translation into linear logic: affine for classical logic, cbn (by default), cbv or 01 for intuitionistic and minimal logic (ordinary.translation)

          Possible values:
          - affine: Classical logic into affine MALL: negation normal form, ∧ as &, ∨ as ⅋
          - cbn:    Girard's call-by-name translation into ILL: A → B as !A ⊸ B, A ∨ B as !A ⊕ !B, hypotheses under !
          - cbv:    Girard's call-by-value translation into ILL: atoms as !a, A → B as !(A ⊸ B), ∧ as ⊗
          - 01:     Liang and Miller's 0/1 translation into ILL, as the LLTP library states it

      --linear
          With --logic, show the linear proof of the image instead of the proof read back as LK or LJ

      --fragment <FRAGMENT>
          Search in this fragment instead of the detected one (search.fragment)
          
          A sequent outside it is an error. A larger fragment than the detected one switches off the prunes that only hold in the smaller one, which is a way to compare them.

          Possible values:
          - mll:       Multiplicatives: ⊗ ⅋
          - mll-units: Multiplicatives and their units: ⊗ ⅋ 1 ⊥
          - all:       Additives only: & ⊕ ⊤ 0
          - mall:      Multiplicatives and additives with units
          - mell:      Multiplicatives and exponentials with units
          - ll:        Every connective

      --engine <ENGINE>
          The engine to search with, or `auto` for the one the fragment and the mode call for (search.engine)
          
          `focus` is focused sequent search, for every classical fragment, with or without units, Mix, exponentials and weakening; `two-sided` the same for every intuitionistic fragment; `net` proof-net search, for MLL without units, with or without Mix, and in intuitionistic mode for IMLL without units by its embedding; `additive` the fast path for two additive-only formulas, in every mode; `horn` the markings of a Petri net, for Horn programs (atoms, implications between tensors of atoms, such implications under !, and one goal that is a tensor of atoms): reachability in linear mode, coverability in affine mode; `essential` proof-net search over essential nets, directed by the intuitionistic reading, for IMLL without units; `inverse` the focused inverse method, a forward search from the axioms in every mode but the ordered ones, which decides without exponentials and with them needs no copy bound, and runs only when named here.
          
          [default: auto]
          [possible values: auto, focus, net, two-sided, additive, horn, essential, inverse]

      --bias <BIAS>
          How the focused engines pick the positive literal of every atom (search.bias)
          
          No choice changes what is provable. `rarer` mostly chains backward from the goal, `factors` forward from the hypotheses, which on Horn clauses under `!`, such as a Petri net, is often much faster but takes one copy per step on a single branch. `auto` takes `rarer` in affine mode, `factors` in linear mode without exponentials, and in linear mode with exponentials runs both searches and answers with the first that decides: alternating on one core, side by side on several.

          Possible values:
          - auto:    `rarer` in affine mode, `factors` in linear mode without exponentials, and in linear mode with exponentials both, each in a search of its own
          - rarer:   The literal with fewer occurrences is positive
          - factors: The literal that is more often a direct factor of a tensor is positive, so that more splits are forced
          
          [default: auto]

      --copies <N>
          How often `?` formulas may be copied on one branch of the proof, or `none` for no bound (search.copies)
          
          The search tries the bounds 0, 1, … in turn. By default it goes on to the next bound until it decides or the time limit passes, and an unknown verdict says which bound it reached. With a bound, a sequent with exponentials that has no proof within it is unknown (exit status 3) unless a smaller bound already exhausted the search space, in which case it is unprovable. Sequents without exponentials are not affected.
          
          [default: none]

      --forward-copies <N>
          How often `?` formulas may be copied on one branch of the forward search that `--bias auto` runs (search.forward_copies)
          
          It applies to a Horn program: clauses such as `!(a * b -o c * d)`, a marking and a goal of atoms, as a Petri net is. There a copy is one step of a chain, and a chain of n steps needs n of them. The forward search never runs within less than `--copies`; on any other sequent, and under Mix, it runs within `--copies`. Without a bound from `--copies` it has no effect: both searches deepen while the time limit lasts.
          
          [default: 30]

      --timeout <DURATION>
          Give up after this long, such as 500ms, 10s, 2m or 1h, or `none` for no limit (clock.time_limit_ms)
          
          The verdict is then unknown (exit status 3). The time counts from the start of the command, so it covers reading and parsing the sequent as well as the search: a sequent that is not read in time is given up on like one that is not decided. Without the limit, the search runs until it decides or is interrupted with Ctrl-C, which with exponentials and no `--copies` bound can be forever. In a session it is each `close`'s limit.
          
          [default: 2s]

      --memo-limit <N>
          The most decided sequents the search remembers at once (search.memo_limit)
          
          When the memo is full it is emptied, which costs time but not correctness. Zero switches the memo off. `--memory-limit` bounds the memo in bytes; this is the finer knob beside it.
          
          [default: 1048576]

      --classical-work <N>
          The most work the classical refutation may do after a search that did not prove the sequent, in formulas evaluated, or 0 for none (search.classical_work)
          
          It looks for truth values of the atoms that make the sequent false read classically (`!` and `?` erased, `*` and `&` as "and", `|` and `+` as "or", `1` and `top` true, `bot` and `0` false), which no provable sequent allows: a search that was unknown is then unprovable (exit status 1), and an exhausted one gets the values as its reason. It runs after the search, past the time limit within this bound (Ctrl-C stops it), and never changes a verdict the search gave.
          
          [default: 67108864]

      --memory-limit <SIZE>
          The most memory the search may hold: a number of bytes with a unit such as 512MiB or 4GiB, or `none` for no limit (limits.memory_bytes)
          
          Counted is the sequent as the search holds it, about 25 bytes for each subformula occurrence, and what grows with the search: what it remembers, the proofs it keeps and what every level of its recursion takes. A memo that no longer fits is emptied first, as at `--memo-limit`; when that is not enough the verdict is unknown (exit status 3). The check of the proof and the derivation built from it are under the same limit: a derivation estimated above it is left out even with `--derivation-limit none`. By default one thread and, after `--pool-after`, a pool beside it search at once, both together within the limit. A png or pdf render is estimated before it starts, its time counted as the memory the renderer fills in it, and left out above the limit (the default is a few seconds of rendering).
          
          [default: 1GiB]

      --recursion-limit <N>
          The deepest nesting of rules on one branch before the search gives up (limits.recursion_depth)
          
          Raise it for sequents with thousands of connectives; the search runs on a thread whose stack grows with the limit.
          
          [default: 2048]

      --work-limit <N>
          The most units of work the search may do, or `none` (limits.work)
          
          A unit is what each engine counts at its polls (a stable sequent or a split for the focused engine, a literal or a failed test for the net engines, a pair for the additive one, a marking for the Horn engine), so a limit gives the same verdict on every machine where a time limit does not; past it the verdict is unknown (exit status 3). `--stats` prints the units a search did.
          
          [default: none]

  -j, --jobs <N>
          How many threads the search may use (search.jobs)
          
          By default one thread searches first, for the time `--pool-after` gives, and then the machine's other threads join it: a small sequent is decided at once and always the same way, a hard one gets every core. A number given here is used from the start, unless `--pool-after` is given too; a number above the machine's parallelism is taken as that, with a note on standard error. More than one runs the focused engine and the net engine on that many threads; the proof found may then differ from run to run, the verdict never does.

      --pool-after <DURATION>
          How long one thread searches before the other threads join it, such as 100ms; 0 starts them at once (clock.pool_after_ms)
          
          The default is 100ms when `--jobs` is not given, and 0 when it is. The single thread goes on searching beside a pool of the other threads, which starts the search afresh, and the first to decide answers; both together hold at most `--memory-limit`. Below three threads there is no single thread: two search on a pool from the start. The additive, the Horn, the essential-net and the inverse engine run on one thread and get no pool.

      --deterministic
          Run the sequential engines, whose proof is a function of the input
          
          The same as `--jobs 1 --schedule turns`, and takes precedence over `--jobs`, `--pool-after` and `--schedule`.

      --test-period <N>
          How often the net engine runs its exact test of correctness, and the essential-net engine its test of the dominator condition: after this many links, or `auto` (search.test_period)
          
          `auto` tests after every link on a small structure and every few links on a large one. The verdict never depends on it.
          
          [default: auto]

      --schedule <SCHEDULE>
          How the two searches of `--bias auto` share one thread (search.schedule)

          Possible values:
          - auto:  In slices on two threads
          - turns: In turns on the calling thread, each turn from the search's start: the same answer and the same counts on every machine
          
          [default: auto]

      --no-check
          Report the proof the search found without checking it (search.check)
          
          By default every proof passes the proof checker, which shares no code with the search, before anything is reported; a proof it rejects is an error (exit status 2), not a verdict.

      --format <FORMAT>
          The output format; by default the one the extension of the `--output` file names (.txt, .json, .tex, .typ, .svg, .png, .pdf, .v), and text otherwise

          Possible values:
          - text:  The verdict on one line, then the derivation as a text tree
          - json:  JSON: prove's outcome (verdict, fragment, mode, engine, statistics, and the proof, which `check` reads), one record a line in a batch; check's verdict and error
          - latex: The verdict as a comment, then the derivation as a LaTeX proof tree of the ebproof package, with the connectives of cmll and amssymb
          - typst: The verdict as a comment, then the derivation as a Typst proof tree: with the curryst package for a low tree, in linlog's own layout for a high one (`--style typst.layout`)
          - svg:   The verdict as an XML comment, then the derivation drawn as an SVG document, set in the Euler Math font unless `--font` names another
          - png:   The derivation drawn as a PNG image, the verdict on standard error; written to a file or a pipe, never to a terminal
          - pdf:   The derivation drawn as a PDF document, its text selectable, the verdict on standard error; written to a file or a pipe, never to a terminal
          - rocq:  The verdict as a comment, then the derivation as a Rocq certificate for the kernel `--kernel` names or the mode chooses: for NanoYalla 1.1.3, the kernel of Click & coLLecT (the nanoyalla directory of github.com/ComputerAidedLL/click-and-collect, built with Rocq 9 and its standard library, no Yalla needed), a lemma stating the sequent one-sided, proved rule by rule, which refuses Mix and the weakening of affine mode; for linlog's own library, a lemma stating the sequent in the mode's calculus, two-sided for intuitionistic logic, proved from the proof term by the library's checker; closed by Qed, `--standalone` adds the imports (`--prelude`), and `--lemma` names the lemma

  -o, --output <PATH>
          Write to this file instead of standard output; the file is made only with a derivation or a net in it (or in JSON, always), and otherwise the verdict goes to standard error

      --net
          Write the proof net of the proof instead of its derivation, for MLL without units, with or without Mix, and with boxes for MELL without units in classical mode, with or without Mix: as text (the sequent, the copies of every ?, its axiom links as pairs of literals with their vertex numbers, and the verdict of the correctness criterion), as json (the net's document in place of the outcome), or drawn as svg, png or pdf (the formula trees with the axiom links as arcs over the literals, every !-box a rectangle around its contents)

  -q, --quiet
          Print only the verdict line, not the derivation; with --output, on standard error, since a file holds a derivation or nothing

      --standalone
          Write a document that compiles on its own instead of a fragment to paste (latex, typst and rocq)

      --no-verdict
          Leave out the verdict line, so that the output is the derivation alone; the exit status still gives the verdict

      --tree <WHEN>
          When to write the derivation, in every format
          
          By default the text tree is printed on a terminal only if it fits: no line wider than the terminal and no more lines than `--screens` screens. Otherwise one line says how large the tree is and how to get it. Into a file or a pipe, and in every other format, the derivation is written whatever its size, up to `--derivation-limit`; `never` writes the verdict alone.

          Possible values:
          - auto:   The text tree on a terminal if it fits, everything else always
          - always: Whatever its size, up to `--derivation-limit`
          - never:  Not at all
          
          [default: auto]

      --screens <N>
          How many screens of lines a text tree may fill and still be printed on a terminal by `--tree auto`, or `none` for any number
          
          [default: 3]

      --abbreviate <CHARS>
          The most characters of a sequent in a verdict line, and of a list of formulas in an error report, or `none` for no limit; a longer one is cut with `…` and the number of its formulas
          
          [default: 200]

      --style <KEY=VALUE>
          Set an option of an output format, such as `labels=subscript`, `latex.open=bare` or `svg.font.family=monospace` (repeatable) (styles.FORMAT.KEY)
          
          KEY is a field of the format's options, dotted into nested ones, as `--style-file` holds them; without a prefix `text.`, `latex.`, `typst.`, `svg.`, `png.`, `pdf.` or `rocq.` it names the format `--format` gives. VALUE is JSON, or else a string: `gap=5`, `ids=true`, `open={"mark":"?"}`, `labels.table.⊸L=⊸_L`. The fields: text: labels, open, bar, gap; latex: form, labels, open, align, ebproof, preamble; typst: form, labels, open, import, page, layout (auto, curryst or linlog: curryst for a tree up to nine inferences high, linlog's own code above), premise_gap, label_gap, band, stroke (lengths for linlog's own layout: a number and pt, mm, cm, in or em); svg: font (family, advances), labels, open, ids, description, font_size, label_size, line_height, premise_gap, literal_gap, label_gap, margin, stroke_width, link_height, link_cap, node_radius, text, line, par, link, highlight, background, essential, input, dominator, net (formulas: a proof net with every subformula written, or compact: only its literals and conclusions written, its inner links circles), net_look (a net's look: textbook or linlog, the default, or its fields premises: dashed or plain, the edges into a ⅋ or ? node; conclusions: raised or bottom, a ! with auxiliary doors written a row above the ? nodes or on the bottom row; why_not: node or rules, a ? node one node or the rules' dereliction, contraction and weakening nodes); png: scale, pixels; pdf: embed_text, compatible, accessible, title, language, date; rocq: form, lemma, prelude, kernel (where the command writes Rocq). `null` lifts a bound (`pixels=null`). Labels are upright, subscript, off or {"table":{RULE:LABEL}}; an open goal is dots, bare, dashed or {"mark":TEXT}

      --style-file <PATH>
          Read the options of the output formats from a JSON file: an object with a key per format (text, latex, typst, svg, png, pdf, and rocq where the command writes Rocq), each holding the fields `--style` names; a field left out keeps its default (styles)

      --font <FONT>
          The math font a drawing (SVG, PNG, PDF) is set and laid out in: euler, stix-two, garamond, asana or new-computer-modern; by default Euler Math (styles.svg.font)

          Possible values:
          - euler:               Euler Math 0.75, upright, after Hermann Zapf's Euler for the AMS
          - stix-two:            STIX Two Math 2.12, in the style of Times
          - garamond:            Garamond-Math 2022-01-03, matching EB Garamond
          - asana:               Asana Math 0.962, in the style of Palatino
          - new-computer-modern: New Computer Modern Math 7.1.1 (Book), the Computer Modern of TeX

      --kernel <KERNEL>
          The Rocq kernel a certificate of linear logic is written for; by default the mode's: nanoyalla for classical linear logic, linlog for Mix, affine and intuitionistic logic (styles.rocq.kernel)

          Possible values:
          - nanoyalla: NanoYalla 1.1.3, the kernel of Click & coLLecT: classical linear logic one-sided, a proof script checked rule by rule
          - linlog:    linlog's own Rocq library (rocq/ of the repository, the package rocq-linlog): every mode in its own calculus, intuitionistic logic two-sided, a proof term checked by the library's checker

      --lemma <NAME>
          The name of the lemma of a Rocq certificate (styles.rocq.lemma)

      --prelude <TEXT>
          The lines a standalone Rocq file starts with, before the lemma, in place of the certificate's own import (styles.rocq.prelude)

      --derivation-limit <SIZE>
          The largest derivation to build, by its estimated size: a number of bytes with a unit such as 64MiB or 2GiB, or `none` for no limit (limits.derivation_bytes)
          
          A derivation writes out the whole sequent at every inference and repeats every subproof that the proof shares, so it can be larger than the proof by any factor. A derivation estimated above the limit is not built, in any format: the verdict is reported without it, with a line that says how large it is, and the exit status is the verdict's. `--format json` writes the proof itself at any size. The drawing of a proof net (`--net`) is estimated before it is drawn and left out above the same limit.
          
          [default: 64MiB]

      --compact <WHEN>
          When a run of one structural rule, such as the weakenings of every unused `?` formula, is drawn as one inference labelled with a star (`?w*`), in every format but rocq (view.compact)

          Possible values:
          - auto:   Where the whole derivation would pass `--derivation-limit` or, as a text tree on a terminal, not fit it
          - always: Always
          - never:  Never: every rule its own inference
          
          [default: auto]

      --stats
          Also print what the search cost: the counters of the engine that ran, a line each, and the time
          
          The focused engines count stable sequents, memo use, splits and the copy bound reached, the net engine literals chosen, links tried and exact tests run, the essential-net engine the same with tests of the dominator condition, the additive one pairs of subformulas, the Horn engine markings, the inverse method the derived sequents taken up, subsumed and kept; every engine its units of work. JSON output always carries the counts; the time is printed only as text, and in a batch's JSON records as `seconds`.

      --settings <PATH>
          Read the settings from a JSON file, before the flags, which override it: an object with any of the keys `clock`, `limits`, `search`, `view`, `styles`, `batch` and `ordinary`, each an object of the fields the flags name in parentheses (`{"search": {"copies": 3}, "limits": {"memory_bytes": null}}`); a field left out keeps the command's default, and a misspelt one is an error; `ordinary` applies under --logic, which names the logic, and `batch.mode` is a batch's mode unless a mode flag is given (one sequent's mode is the flags')

      --files-from <LIST>
          Read the paths of the inputs from this file, one per line, or `-` for standard input, read as it streams

      --null
          The paths of --files-from are separated by NUL, as `find -print0` writes them

      --workers <N>
          How many sequents of a batch are decided at once, across the cores; by default as many as the machine runs threads, fewer when --batch-memory does not hold that many searches at --memory-limit each (batch.workers)

      --cores <WHERE>
          Where a batch's threads go (batch.cores)
          
          Across the sequents, each gets one thread for its --timeout, as with --deterministic, which answers the most sequents in a given time and gives every answer as a function of its input; a sequent that needs the pool a single call races beside one thread, or more time on one thread, stays unknown there. Within, each sequent gets the race on every thread, as a single call does. To decide what a batch across left unknown, run those sequents again with --cores within or a longer --timeout.

          Possible values:
          - auto:   Across the sequents when the batch has at least as many as --workers, else within; within on a stream from standard input, whose next question may wait for an answer
          - across: One sequent per worker, each on one thread: the sequential engines, as with --deterministic
          - within: One sequent at a time, with the threads --jobs gives
          
          [default: auto]

      --batch-memory <SIZE>
          The most memory all the searches of a batch hold together: a size such as 8GiB, or `none`; by default half the memory the process may use (the machine's, or its control group's limit where one is set) (batch.total_memory_bytes)
          
          Each search holds at most --memory-limit, and as many run at once as this holds; within one sequent the race of one thread and a pool is two searches, which share it.

      --batch-timeout <DURATION>
          Give up on the rest of a batch after this long, or `none` (clock.batch_time_limit_ms)
          
          The sequents still searched are stopped and those not begun are unknown; --timeout is each sequent's own limit.
          
          [default: none]

      --isolate
          Decide each sequent of a batch in a child process of its own, so that one that exhausts the memory or the stack ends only itself

  -h, --help
          Print help (see a summary with '-h')

Sequent syntax: `A, B |- C, D` (or `⊢`), either side may be empty.
  tensor  A * B, A ⊗ B        par   A | B, A par B, A ⅋ B
  with    A & B               plus  A + B, A ⊕ B
  linear implication  A -o B, A ⊸ B
  negation  ~A, A^            exponentials  !A, ?A
  units  1, bot, ⊥, top, ⊤, 0
