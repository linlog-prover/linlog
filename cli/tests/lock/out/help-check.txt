Check a proof read from JSON, as `prove --format json` writes it

The mode comes from the flags, not from the file: pass the flags the proof was found with. The exit status is 0 for a valid proof, 1 for an invalid one, 3 when the check was given up at a limit (neither valid nor invalid), and 2 for an error. With `--format json` the verdict is `{"version", "verdict", "mode"}`, the verdict `valid`, `invalid` or `unknown`, with the library's `error` object and its `message` with formulas for the last two.

Usage: linlog check [OPTIONS] [PROOF]

Arguments:
  [PROOF]
          The proof file, or standard input when absent or `-`

Options:
      --memory-limit <SIZE>
          The most memory the check may hold: a number of bytes with a unit such as 512MiB or 4GiB, or `none` for no limit
          
          A proof whose check would pass it is neither valid nor invalid: the verdict is unknown (exit status 3). A derivation estimated above it is left out, as past `--derivation-limit`, and so is a png or pdf render; see `prove --memory-limit` (limits.memory_bytes).
          
          [default: 1GiB]

      --timeout <DURATION>
          Give up after this long, such as 500ms, 10s, 2m or 1h, or `none` (clock.time_limit_ms)
          
          A proof file can make its check quadratic (a large shared subproof read by many nodes); the verdict is then unknown (exit status 3). The time counts from the start of the command and covers the derivation drawn after the check.
          
          [default: 2s]

      --work-limit <N>
          The most units of work the check may do, or `none` (limits.work)
          
          A unit is a node of the proof or an entry of a sequent a node is handed; past the limit the verdict is unknown (exit status 3).
          
          [default: none]

      --occurrence-limit <N>
          The most subformula occurrences the proof's sequent may have, or `none` (limits.occurrences); see `prove --occurrence-limit`
          
          [default: 50000000]

  -i, --intuitionistic
          Intuitionistic linear logic: one formula on the right of ⊢, pars only as implications, and two-sided derivations

  -a, --affine
          Affine logic: a hypothesis may go unused (weakening)

      --mix
          Allow the Mix rule, which proves ⊢ Γ, Δ from ⊢ Γ and ⊢ Δ

      --cyclic
          Cyclic linear logic: the order of the formulas counts, up to rotation, with no exchange (unit-free MLL); the sequent's text is read with the dual of a product reversed, ~(A * B) as ~B par ~A, and the formulas left of ⊢ in the reverse order

      --lambek
          The Lambek calculus: intuitionistic and in the order written, with the divisions A \ B and B / A beside A * B (unit-free), every sequent with a formula left of ⊢; the text is read as --cyclic reads it

      --empty-antecedents
          With --lambek, allow sequents with no formula left of ⊢ (the calculus L*)

      --format <FORMAT>
          The output format; by default the one the extension of the `--output` file names (.txt, .json, .tex, .typ, .svg, .png, .pdf, .v), and text otherwise

          Possible values:
          - text:  The verdict on one line, then the derivation as a text tree
          - json:  JSON: prove's outcome (verdict, fragment, mode, engine, statistics, and the proof, which `check` reads), one record a line in a batch; check's verdict and error
          - latex: The verdict as a comment, then the derivation as a LaTeX proof tree of the ebproof package, with the connectives of cmll and amssymb
          - typst: The verdict as a comment, then the derivation as a Typst proof tree: with the curryst package for a low tree, in linlog's own layout for a high one (`--style typst.layout`)
          - svg:   The verdict as an XML comment, then the derivation drawn as an SVG document, set in the Euler Math font unless `--font` names another
          - png:   The derivation drawn as a PNG image, the verdict on standard error; written to a file or a pipe, never to a terminal
          - pdf:   The derivation drawn as a PDF document, its text selectable, the verdict on standard error; written to a file or a pipe, never to a terminal
          - rocq:  The verdict as a comment, then the derivation as a Rocq certificate for the kernel `--kernel` names or the mode chooses: for NanoYalla 1.1.3, the kernel of Click & coLLecT (the nanoyalla directory of github.com/ComputerAidedLL/click-and-collect, built with Rocq 9 and its standard library, no Yalla needed), a lemma stating the sequent one-sided, proved rule by rule, which refuses Mix and the weakening of affine mode; for linlog's own library, a lemma stating the sequent in the mode's calculus, two-sided for intuitionistic logic, proved from the proof term by the library's checker; closed by Qed, `--standalone` adds the imports (`--prelude`), and `--lemma` names the lemma

  -o, --output <PATH>
          Write to this file instead of standard output; the file is made only with a derivation or a net in it (or in JSON, always), and otherwise the verdict goes to standard error

      --net
          Write the proof net of the proof instead of its derivation, for MLL without units, with or without Mix, and with boxes for MELL without units in classical mode, with or without Mix: as text (the sequent, the copies of every ?, its axiom links as pairs of literals with their vertex numbers, and the verdict of the correctness criterion), as json (the net's document in place of the outcome), or drawn as svg, png or pdf (the formula trees with the axiom links as arcs over the literals, every !-box a rectangle around its contents)

  -q, --quiet
          Print only the verdict line, not the derivation; with --output, on standard error, since a file holds a derivation or nothing

      --standalone
          Write a document that compiles on its own instead of a fragment to paste (latex, typst and rocq)

      --no-verdict
          Leave out the verdict line, so that the output is the derivation alone; the exit status still gives the verdict

      --tree <WHEN>
          When to write the derivation, in every format
          
          By default the text tree is printed on a terminal only if it fits: no line wider than the terminal and no more lines than `--screens` screens. Otherwise one line says how large the tree is and how to get it. Into a file or a pipe, and in every other format, the derivation is written whatever its size, up to `--derivation-limit`; `never` writes the verdict alone.

          Possible values:
          - auto:   The text tree on a terminal if it fits, everything else always
          - always: Whatever its size, up to `--derivation-limit`
          - never:  Not at all
          
          [default: auto]

      --screens <N>
          How many screens of lines a text tree may fill and still be printed on a terminal by `--tree auto`, or `none` for any number
          
          [default: 3]

      --abbreviate <CHARS>
          The most characters of a sequent in a verdict line, and of a list of formulas in an error report, or `none` for no limit; a longer one is cut with `…` and the number of its formulas
          
          [default: 200]

      --style <KEY=VALUE>
          Set an option of an output format, such as `labels=subscript`, `latex.open=bare` or `svg.font.family=monospace` (repeatable) (styles.FORMAT.KEY)
          
          KEY is a field of the format's options, dotted into nested ones, as `--style-file` holds them; without a prefix `text.`, `latex.`, `typst.`, `svg.`, `png.`, `pdf.` or `rocq.` it names the format `--format` gives. VALUE is JSON, or else a string: `gap=5`, `ids=true`, `open={"mark":"?"}`, `labels.table.⊸L=⊸_L`. The fields: text: labels, open, bar, gap; latex: form, labels, open, align, ebproof, preamble; typst: form, labels, open, import, page, layout (auto, curryst or linlog: curryst for a tree up to nine inferences high, linlog's own code above), premise_gap, label_gap, band, stroke (lengths for linlog's own layout: a number and pt, mm, cm, in or em); svg: font (family, advances), labels, open, ids, description, font_size, label_size, line_height, premise_gap, literal_gap, label_gap, margin, stroke_width, link_height, link_cap, node_radius, text, line, par, link, highlight, background, essential, input, dominator, net (formulas: a proof net with every subformula written, or compact: only its literals and conclusions written, its inner links circles); png: scale, pixels; pdf: embed_text, compatible, accessible, title, language, date; rocq: form, lemma, prelude, kernel (where the command writes Rocq). `null` lifts a bound (`pixels=null`). Labels are upright, subscript, off or {"table":{RULE:LABEL}}; an open goal is dots, bare, dashed or {"mark":TEXT}

      --style-file <PATH>
          Read the options of the output formats from a JSON file: an object with a key per format (text, latex, typst, svg, png, pdf, and rocq where the command writes Rocq), each holding the fields `--style` names; a field left out keeps its default (styles)

      --font <FONT>
          The math font a drawing (SVG, PNG, PDF) is set and laid out in: euler, stix-two, garamond, asana or new-computer-modern; by default Euler Math (styles.svg.font)

          Possible values:
          - euler:               Euler Math 0.75, upright, after Hermann Zapf's Euler for the AMS
          - stix-two:            STIX Two Math 2.12, in the style of Times
          - garamond:            Garamond-Math 2022-01-03, matching EB Garamond
          - asana:               Asana Math 0.962, in the style of Palatino
          - new-computer-modern: New Computer Modern Math 7.1.1 (Book), the Computer Modern of TeX

      --kernel <KERNEL>
          The Rocq kernel a certificate of linear logic is written for; by default the mode's: nanoyalla for classical linear logic, linlog for Mix, affine and intuitionistic logic (styles.rocq.kernel)

          Possible values:
          - nanoyalla: NanoYalla 1.1.3, the kernel of Click & coLLecT: classical linear logic one-sided, a proof script checked rule by rule
          - linlog:    linlog's own Rocq library (rocq/ of the repository, the package rocq-linlog): every mode in its own calculus, intuitionistic logic two-sided, a proof term checked by the library's checker

      --lemma <NAME>
          The name of the lemma of a Rocq certificate (styles.rocq.lemma)

      --prelude <TEXT>
          The lines a standalone Rocq file starts with, before the lemma, in place of the certificate's own import (styles.rocq.prelude)

      --derivation-limit <SIZE>
          The largest derivation to build, by its estimated size: a number of bytes with a unit such as 64MiB or 2GiB, or `none` for no limit (limits.derivation_bytes)
          
          A derivation writes out the whole sequent at every inference and repeats every subproof that the proof shares, so it can be larger than the proof by any factor. A derivation estimated above the limit is not built, in any format: the verdict is reported without it, with a line that says how large it is, and the exit status is the verdict's. `--format json` writes the proof itself at any size. The drawing of a proof net (`--net`) is estimated before it is drawn and left out above the same limit.
          
          [default: 64MiB]

      --compact <WHEN>
          When a run of one structural rule, such as the weakenings of every unused `?` formula, is drawn as one inference labelled with a star (`?w*`), in every format but rocq (view.compact)

          Possible values:
          - auto:   Where the whole derivation would pass `--derivation-limit` or, as a text tree on a terminal, not fit it
          - always: Always
          - never:  Never: every rule its own inference
          
          [default: auto]

      --settings <PATH>
          Read the settings from a JSON file, before the flags, which override it: an object with any of the keys `clock`, `limits`, `search`, `view`, `styles`, `batch` and `ordinary`, each an object of the fields the flags name in parentheses (`{"search": {"copies": 3}, "limits": {"memory_bytes": null}}`); a field left out keeps the command's default, and a misspelt one is an error; `ordinary` applies under --logic, which names the logic

  -h, --help
          Print help (see a summary with '-h')
