# Beside the other provers, 2026-10-15

One run of linlog and the other provers of linear logic on the same
4 811 problems (the LLTP library, qcover's coverability problems and
linlog's generated families), on 2026-10-15 on an Intel Core Ultra X9
388H (16 cores, 64 GB, Linux 7.2.9): the sequential tools and linlog's
one-thread column each on one efficiency core (cores 6–11, six streams
side by side), linlog's default on the four low-power cores (12–15),
every run under 10 s and 4 GiB, measured by BenchExec 3.27. linlog was
built from commit `60226b2c`, every other tool at the version the flake
pins. The rows are `bench/comparison/2026-10-15/runs.csv` (62 543 runs),
the tables `ranking.md` beside them, and
[bench/TOOLS.md](https://github.com/linlog-prover/linlog/blob/main/bench/TOOLS.md#results)
says how each tool was run and discusses every result; the tables below
are its own.

## The scatter plots

Each plot sets linlog on one thread against one tool on every problem
both cover, a point per problem, the tool's time across and linlog's
up, both logarithmic; a problem not solved is drawn on the dashed line
of the 10 s limit. A point below the diagonal is a problem linlog
solved faster. Against every other prover most points lie below it:
of the 4 495 problems linlog and Sympli both cover, linlog is faster by
more than a tenth on 3 294 and slower on 551, Sympli's refutations
that linlog leaves at its limit making the row along the top; against
Maude, llprover, linTAP, lolli and LinearOne no point lies above it.
Against linlog's own default, which runs on the slower low-power cores
and races a second search, most points lie on the diagonal.
