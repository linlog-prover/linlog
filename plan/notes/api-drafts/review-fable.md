## Issues

**1. should-fix — §7.5 "What changes in the pinned forms" (2052–2070), with §8.5 (2261–2272), §5.2 (1491–1493) and the stage report's area table.** A fourth change of the behaviour lock is implied and not named. Lock commit (1) (area 3.1) pins `work` and `forward_copies` in `statistics`, but `Statistics` has neither today (`core/src/search/mod.rs:1462–1490`: `nodes, memo_hits, memo_entries, splits, links, tests, copies`), and the engines count `work` only after area 3.2's "progress stop at every poll site … a commit of its own" (§5.2), while `forward_copies` needs F144's split of the two levels, also search work. Either commit (1) pins `"work": 0` and area 3.2 reblesses every outcome line (a fourth lock commit, against "Nothing else in this design moves a pinned form"), or the search area's counter must land before commit (1). The same ordering gap exists for the stop: §5.6 puts `stop: impl FnMut(Progress) -> bool` on every public call in area 3.1, but the poll sites (`Stop::Closure(&mut dyn FnMut() -> bool)`, `search/mod.rs:46–62`) change in area 3.2, so area 3.1 must ship a shim passing `Progress::default()` and R243's sum test must wait. Also `checked` (§7.3, 1940) is absent from commit (1)'s key list. *Fix:* in §7.5 say which area lands `work`/`forward_copies` and when relative to commit (1), name the shim, and add `checked` to the list.

**2. should-fix — §5.4 "The race" (1532–1552).** The text contradicts itself on `--jobs 2`: the doc comment says "a pool of `threads − 1` (at least two) beside it", the prose says "`threads` counts both, so `--jobs 2` runs two threads (F168); below three threads there is no race." With `threads = 2` the first gives three threads (today's bug), the second says no race, and what runs is unstated: a pool of two from the start (then `add_pool` is never asked and the default bias's scheme differs, §5.3) or one thread alone. F168's fix offers both; R85 needs the harness's default column to be exactly what the command runs. *Fix:* state the rule for `threads ≤ 2` in the doc comment and drop "(at least two)" or qualify it.

**3. should-fix — §7.1 "Reading" (1829–1832) and §2.4 last row (246); §14.1 T1.** "A document without `version` reads as level 1 and may use the pre-release names (`ids`, `var_dict`, `proof`, a net's `mix` as today, a mode as an object of flags)" is a compatibility shim for pre-release files shipped permanently in 0.1.0. D18 (`plan/README.md:721–727`) and rubric S17 forbid keeping a replaced item beside its successor, and the step prompt lists "no compatibility aliases before the release" as a constraint. The reason given (the proof files of 2026-09-30 and today's fixtures still load) names pre-release artefacts that the lock commits regenerate anyway; the shim doubles each reader's accepted grammar (fuzz surface, `Within`'s code) for ever. *Fix:* either read `version`-less documents as level 1 with the new names only and regenerate the fixtures in commit (1), or put the alias to the author as a decision of §14.2 (today it appears only as T1's "other answer").

**4. should-fix — §3.1 "Readers name their bound" (327–336) and §7.1 "Text" (1858–1861).** The reserved words `forall`, `exists` are refused as JSON atom names, but what the *text* parser does with them at 28 is not said; today `|- forall` parses as an atom (impact-quantifiers §1 item 4; `core/src/parse/mod.rs` has no such keyword). §7.1's own rule, "the text syntax … grows by new tokens only, never by a new meaning of text that reads today", then forbids step 38 from making `forall` a binder keyword unless 28 reserves it in the parser too. *Fix:* state that `parse_within` (and so `lltp::read`, `mist::read`) refuses `forall`/`exists` as identifiers from 28 (`∀`/`∃` are errors already), lock-neutral unless a fixture uses them.

**5. should-fix — §10.10 (f), the prune table (2798), with §3.2's cost paragraph (401–406).** "counts, the count equation, the bias: per ground atom as today, per predicate symbol for open atoms" is unsound as written. In `∀x.p(x) ⊢ p(a)` the symbol `p` has an open atom `p(#0)` and a ground atom `p(a)`; counting `p(a)` "as today" gives `Unbalanced { atom: p(a) }` and a wrong `Unprovable`. The sound rule is: a symbol with any open atom is counted per symbol for all its atoms; only symbols whose atoms are all ground keep today's per-atom count. This is exactly where decision 1's "correct by construction for ground atoms" argument stops, and the row is the text 38's implementer will follow. `Unbalanced { atom }` cannot name a symbol; 38's walk-through left "Unbalanced per symbol" to 38, which the open `refutation.kind` allows. *Fix:* rewrite the row; say the count refutation is skipped or per-symbol for any symbol with an open atom.

**6. note — §14.2 decision 20 (3178) and §11.5 (2983–3016).** D-7 is adopted on instruction counts alone. `design-constraints.md` D-7 (lines 212–215) and D17 (`plan/README.md:712–719`) make "counters identical and pinned CPU time within a few percent" the acceptance test; G3 was never run (§11.5; `spike-report.md` line 5 "no G3", line 135). M3 adds about 166 KB (7 %) of text, 140 KB of it `Framed`; callgrind's instruction count does not see the instruction cache, which is what a second monomorphised engine costs. §11.5 says this honestly; decision 20's row ("measured: … within the gates") and the stage report's "free" do not. D-7 is crate-private and 38 keeps the duplicated-path exit, so nothing public rests on it. *Fix:* word decision 20 as provisional on a pinned-time run, and make G3 the first measurement of step 37's lift commit (§10.9), on an idle machine.

**7. should-fix (contradiction) — P3 (49–53) against §4.1 (1204), §4.4, §3.8 (750–756), §3.10 (907), §3.12 (1059), §8.6 (2299).** P3 and §4.1 say "a variant of a marked enum that carries data has named fields" / "named fields only (F31)", yet the design writes `Error::{Parse(Box<ParseError>), Check(CheckError), Net(Box<NetError>), Step(StepError), Refused(Refusal), Unsupported(rocq::Unsupported)}`, `CheckError::Invalid(Box<Invalid>)`, `Fault::{Shape(ShapeError), Succedents(usize), Kind(Member), NotUnderQuest(Member), Conclusion(Dyadic)}`, `Refutation::Unbalanced(Unbalanced)`, `NotTaken::Mode(Mode)`, `Split::Left(Vec<usize>)`. Stage 3 will otherwise decide per site, and no lint catches the drift. *Fix:* state the exception (a newtype variant whose payload is itself `#[non_exhaustive]` needs no named fields) and convert the rest (`Fault::Succedents`, `Fault::Kind`, `NotUnderQuest`, `NotTaken::Mode`, `Split::Left`) or drop the sentence.

**8. note — small internal mismatches a fix session will stumble on.** §2.4 (217) `goal(GoalId) -> &[Member]` vs §3.10 (915) `Option<&[Member]>`. - **Decision 19:** mathematically right: in cyclic MLL `⊢ (a ⊗ b)⊥, a, b` with the reversing dual is `⊢ b⊥, a⊥, a, b`, provable with wrap-around adjacency; with the order-keeping dual `⊢ a⊥, b⊥, a, b` has no adjacent axiom pair. The "Not merged" note of the register (R56 against R57/R58/R119) is honoured by refusing cut in ordered modes. What 36 must still state: a `Sequent` carries no record of which dual lowered it, so a JSON sequent proved in cyclic mode is taken as already lowered.
- **Register coverage:** every entry of the sections §13 claims (Wire forms through Export) is cited or inside a cited range; R42/R48 (wasm, `run_local`), R47 (`Schedule::Turns`), R85/R18 (one account), R130, R135, R138, R149, R243, R247 are each placed where §13 says.
